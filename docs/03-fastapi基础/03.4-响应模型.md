# 03.4 · 响应模型：出口也要管

> 练习代码：[04-响应模型.py](../../projects/03-fastapi基础/03.4-响应模型/04-响应模型.py)

## 核心概念

- **`response_model` 是响应的白名单**：函数返回值里多带的字段（password、进价）会被过滤，只有模型声明的字段放行。与 03.3 对偶——请求模型管入口，响应模型管出口。
- **文档同步**：/docs 按 `UserOut` 展示响应结构，敏感字段连文档里都没有——前端照着写类型。
- **`status_code` 给成功标语义**：`200` 查询（默认）、`HTTP_201_CREATED` 创建、`HTTP_204_NO_CONTENT` 删除（无响应体）；写在装饰器上，文档同步显示预期状态码。
- **读请求头 / Cookie**：`Annotated[str | None, Header()]`——`Header()` 自动把 `user_agent` 映射成 HTTP 头 `User-Agent`（下划线 ↔ 连字符）；`Annotated[类型, 附加信息]` 是 FastAPI 的推荐写法。
- **写 Cookie / 响应头**：给函数声明 `response: Response` 参数即可 `set_cookie`；返回值照常返回，互不影响。

## 关键代码

```python
class UserOut(BaseModel):
    username: str
    email: str                       # 没有 password——白名单

@app.get("/users/{username}", response_model=UserOut)
def get_user(username: str) -> dict:
    # 返回值带密码，但 response_model 只放行声明的字段
    return {"username": username, "email": "...", "password": "绝密123456"}

@app.post("/orders", status_code=status.HTTP_201_CREATED)  # 创建成功用 201
def create_order(order: OrderIn) -> dict:
    return {"order_id": 1, "item": order.item}

@app.get("/login")
def login(response: Response) -> dict:                     # 声明 Response 参数
    response.set_cookie(key="session_id", value="abc123", max_age=3600)
    return {"message": "已种下 session_id Cookie"}          # 返回值照常
```

## 运行结果

- `/users/xxx` 的响应里看不到 `password`，/docs 的 Responses 结构里也没有；
- POST `/orders` → **201**（/docs 里预期状态码同步显示）；
- Cookie 闭环：先访问 `/login` 种 Cookie，再访问 `/whoami` 看 `session_id` 出现；浏览器 DevTools → Application → Cookies 里能亲眼看到。

## 常见坑

1. **响应模型声明了字段但返回值里没有** → 响应缺字段：不报错，但前端拿不到——白名单只滤多、不补少。
2. **`204` 还想返回数据**：204 的定义就是无 body；要带数据用 200/201。
3. **参数名只能用下划线**：写 `user_agent` 靠 `Header()` 自动映射连字符版本，别直接写 `user-agent`。
4. **Cookie 看不到**：先访问 /login 种 Cookie；/docs 的请求从浏览器发出才带得上 Cookie。
5. **Cookie 值是 percent-encoded 乱码**：中文会被编码成 `%E6%88%91…`，用 `unquote()` 还原（练习 /whoami 里的处理）。
