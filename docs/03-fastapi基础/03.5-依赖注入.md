# 03.5 · 依赖注入：公共逻辑只写一遍

> 练习代码：[05-依赖注入.py](../../projects/03-fastapi基础/03.5-依赖注入/05-依赖注入.py)

## 核心概念

- **`Depends` 把「多个接口共用的逻辑」抽成普通函数**：路由在参数里声明「我需要它」，框架负责调用、传参、组装——FastAPI 最独特的特性。
- **依赖的参数自动成为查询参数**：`pagination(skip=0, limit=10)` 被 `/books`、`/reviews` 共用，分页参数自动出现在每个使用者的接口上，不用在路由里再写一遍。
- **依赖链**：依赖的参数里还能 `Depends(别的依赖)`——token 校验 → 取当前用户 → 判断权限，层层组装，每层都是独立函数、可单独测试（02.7 的 pytest 正好用上）。
- **yield 依赖 = 前逻辑 + 后逻辑**：`yield` 前是 setup（请求前）、之后是 teardown（响应后），02.3 生成器的老朋友——数据库会话的标准形态。
- **`Annotated[类型, Depends(函数)]` 是现代写法**：起个短名（`Page = Annotated[...]`）多处复用更清爽。
- **全局 / 组级依赖（知道即可）**：`FastAPI(dependencies=[...])` 和 router 的 `dependencies` 参数，给一批路由统一加检查。

## 关键代码

```python
def pagination(skip: int = 0, limit: int = 10) -> dict:
    """这些参数会自动成为「使用这个依赖的每个接口」的查询参数。"""
    return {"skip": skip, "limit": limit}

Page = Annotated[dict, Depends(pagination)]   # 起短名，多处复用

@app.get("/books")
def list_books(page: Page) -> dict:           # /books?skip=2&limit=5
    return {"数据源": "图书表", **page}

def fake_db_session():                 # yield 依赖：前逻辑 + 后逻辑
    print("→ [依赖] 打开连接")          # yield 前 = setup（请求前）
    yield "conn-1"                     # 交给路由函数用
    print("← [依赖] 关闭连接")          # yield 后 = teardown（响应后）
```

## 运行结果

- `/books?skip=2&limit=5` 和 `/reviews` 都收到分页——分页逻辑只有一份；
- `/admin-dashboard?token=admin-token` → `allowed=true`；换 `guest-token` → `false`（依赖链三层函数各管一层）；
- 访问 `/db-info` 后看运行终端：打开连接 → 路由执行 → 关闭连接，两行 print 的顺序就是生命周期。

## 常见坑

1. **`page: dict = Depends(pagination)`（不带 Annotated）也能跑**，但和 Annotated 混写难读——风格统一用 Annotated。
2. **依赖函数的参数没默认值 → 变成必填查询参数**，客户端不传就 422。
3. **别把「请求状态」存成模块级全局变量**：每个请求都会执行依赖，会互相踩。
4. **yield 依赖的 teardown 在响应之后执行**：别在里面改响应内容（改响应用 03.4 的 `Response` 参数）。
5. **字面量联合类型必须写 `Literal[...]`**：`"skip" | "limit"` 静态检查器认、运行时是 TypeError（练习注释踩过）。
