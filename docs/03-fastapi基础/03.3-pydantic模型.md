# 03.3 · Pydantic 模型：写模型就是写校验

> 练习代码：[03-模型.py](../../projects/03-fastapi基础/03.3-pydantic模型/03-模型.py)

## 核心概念

- **`BaseModel` 的字段注解 = 数据契约**：缺必填字段、类型对不上、超出范围，全部自动 422，错误信息里指明是哪个字段。
- **校验通过后字段是干净的正确类型**：JSON 里传 `"45"` 会自动转成 `45.0`；`book.model_dump()` 把模型转成 dict（旧教程的 `.dict()` 是它的前身）。
- **`Field` 给字段加规则**：`gt/ge/le` 管数字范围、`min_length` 管字符串长度、`default_factory` 管可变默认值、`description` 直接显示在 /docs。
- **可选字段 `str | None = None`**：「没传」（用默认值）和「传了 null」是两回事——03.4 的 `exclude_unset` 会兑现这个区别。
- **嵌套模型**：字段类型是另一个 `BaseModel`，请求体 JSON 按结构逐层校验；`list[Book]` 表示整批数据。

## 关键代码

```python
class ReviewIn(BaseModel):
    content: str = Field(min_length=5, max_length=200)   # 拒收空串和超长
    rating: int = Field(ge=1, le=5, description="评分 1~5 星")  # 说明进 /docs

class DetailedBookIn(BaseModel):
    title: str
    author: AuthorIn                               # 嵌套：按结构逐层校验
    tags: list[str] = Field(default_factory=list)  # 可变默认值的标准写法

@app.post("/reviews")
def create_review(review: ReviewIn) -> dict:
    return review.model_dump()   # 校验通过 → 干净类型 → 转 dict 返回
```

## 运行结果

- `rating=6` → 422，`loc: ["body","rating"]`、`msg: "Input should be less than or equal to 5"`（练习 TODO 1 里已实拍抄录）；
- `author` 传成字符串（不是对象）→ 422，`loc` 会指到里层字段；
- /docs 观察点：`Field(description=...)` 出现在接口文档里；`BookCreate`（期末大作业核心资产）在 `/books-v2` 上岗。

## 常见坑

1. **边界没想清楚**：`ge=0` 允许 0 元书，「必须 > 0」得用 `gt=0`；同理评分 `ge=1` 会把 0.5 分拦掉（练习里 price/rating 的订正注释）。
2. **`Field()` 只写约束不给默认值 → 字段反而变必填**：练习 TODO 3 实测「不传 → 422 Field required」；可选字段的正确写法就是普通默认值 `= None`。
3. **校验失败先读 422 的 `loc` / `msg`**：`loc` 指明哪个字段、`msg` 说明违反什么规则——读它比猜快。
4. **可变默认值**：`tags: list[str] = []` 在 Pydantic 里其实安全（默认值会被深拷贝），但惯例仍写 `Field(default_factory=list)`，和 dataclass 保持同一习惯。
5. **子类继承模型别再写一遍 `BaseModel`**：`class BookCreate2(BookCreate)` 字段全部自动带过来（练习订正注释）。
