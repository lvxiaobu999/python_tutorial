# 01.7 · 异常处理

> 练习代码：[01-异常与自定义.py](../../projects/01-python基础/01.7-异常处理/01-异常与自定义.py)

## 核心概念

- **异常 = 运行时无法正常完成的情况**：`int("abc")` 抛 `ValueError`，`10 / 0` 抛 `ZeroDivisionError`；不处理就程序中断并打印 traceback（标出出错行和调用链）。
- **try / except / else / finally 四块职责**：try 放可能出错的代码；except 处理指定异常；else 在 try 成功后执行；finally 收尾（关文件、释放资源），无论成败都执行。
- **执行顺序速记**：没出错 try→else→finally；出错被捕获 try→except→finally；出错没捕获 try→finally 仍执行→异常继续上抛。
- **捕获要具体**：首选 `except 具体异常`，多种可写元组 `except (ValueError, TypeError):`；`except Exception` 只在程序顶层兜底；裸 `except:` 禁用。
- **raise 主动抛出**：输入不满足业务规则时主动报错；自定义异常继承 `Exception`，还能携带业务字段供处理方读取。
- **两种防御风格**：EAFP（先做、错了再捕，`try: v = d["k"] except KeyError:`）比 LBYL（先检查再行动）更 Pythonic。

## 关键代码

```python
def parse_age(value):
    try:
        age = int(value)                      # 可能出错：int("abc") 抛 ValueError
        if age < 0:
            raise ValueError("年龄不能为负数")  # 业务规则不满足时主动抛
    except ValueError as error:               # as error 拿到异常对象
        print("输入无效：", error)
        return None
    else:
        return age                            # try 没出错才执行
    finally:
        print("年龄解析结束")                  # 无论成败都执行

print(parse_age("18"))
print(parse_age("abc"))
```

## 运行结果

```text
年龄解析结束
18
输入无效： invalid literal for int() with base 10: 'abc'
年龄解析结束
None
```

## 常见坑

- **裸 `except:` 禁用**：吞掉一切异常（连 Ctrl+C 都吞），出 bug 时无从排查 → 永远写具体异常类型。
- **`except Exception` 写在最前面**：多个 except 分支从上到下匹配、命中一个就跳过其余，父类在前会挡住后面的子类分支 → 子类放前面。
- **except 离错误源太远**：try 块塞太多代码，中间无关代码的异常会被误捕 → 用 `else` 把「可能出错的代码」和「依赖其结果的后续代码」分开。
- **`finally` 里写 `return`**：会吞掉异常和返回值，清理动作只做关资源、记日志这类事。
- **`else` 不是 if/else 的那个 else**：它属于 try 语句，含义是「try 成功后才执行」。
- **自定义异常忘记继承 `Exception`**：raise 时会报 TypeError，类定义写成 `class XxxError(Exception)` 即可。
