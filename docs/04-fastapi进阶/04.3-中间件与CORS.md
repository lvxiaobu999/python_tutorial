# 04.3 · 中间件与 CORS

> 练习代码：[03-中间件.py](../../projects/04-fastapi进阶/04.3-中间件与CORS/03-中间件.py)

## 核心概念

- **中间件 = 包住整个应用的洋葱层**：请求进来先穿过它（入向），`await call_next(request)` 放行里层，响应出去再穿回来（出向）。比 03.5 的 yield 依赖管得宽——404、HTTPException、/docs 页面也照样穿过。
- **注册顺序 = 洋葱层次**：后注册的包在**最外层**。CORS 注册在计时中间件之后 → 预检 OPTIONS 被拒时请求根本没穿进内层，内层日志不打印。
- **CORS 规矩定在浏览器，不在服务器**：页面 fetch 别的源（协议+域名+端口缺一即跨域）时，响应必须带 `Access-Control-Allow-Origin` 浏览器才把响应交给页面的 JS。curl / Postman / TestClient 没这道岗，怎么发都通。
- **数据往哪带**：入向（进路由前）用 `request.state`，出向用 `response.headers`。

## 关键代码

```python
@app.middleware("http")
async def add_process_time(
    request: Request,
    call_next: Callable[[Request], Awaitable[Response]],   # 类型标在「源头」
) -> Response:
    start = time.perf_counter()
    response = await call_next(request)      # 放行：交给洋葱里层
    response.headers["X-Process-Time-ms"] = f"{(time.perf_counter() - start) * 1000:.1f}"
    return response
```

X-Request-ID 的「两头对上」：入向生成并 `request.state.request_id = ...`（路由里可取回），出向 `response.headers["X-Request-ID"] = ...`——排查日志靠它串联同一次请求。

## 运行结果

- 随便发什么请求（包括打错的路径）→ 终端一行 `[中间件]` 日志，响应头多 `X-Process-Time-ms`；
- `GET /state` 返回的 request_id 与响应头 X-Request-ID 相同——同一次请求两头对得上；
- cors-test.html：白名单内的 Origin 响应带 ACAO 头，名单外的没有。

## 常见坑

1. **request.headers 只读**：赋值直接 TypeError；往里带数据用 `request.state`。
2. **cast 是贴标签不是转换**：`cast(str, uuid.uuid4())` 运行时还是 UUID；真转换要 `str()`。更好的做法是把类型标在 call_next 签名（源头），Pylance 全程可推断，根本不需要 cast。
3. **`allow_origins=["*"]` 与 `allow_credentials=True` 不能同用**：浏览器规范禁止（ACAO:* 的响应不许再声明可携带 Cookie）。starlette 遇到不报错，而是悄悄回显请求的 Origin——防护等于没有，自己别这么配。
4. **必须是 `async def`**：要 `await` 里层算完才能拿到响应（02.5 事件循环）。
