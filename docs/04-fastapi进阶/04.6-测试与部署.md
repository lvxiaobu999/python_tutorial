# 04.6 · 测试与部署（pytest + TestClient）

> 练习代码：[06-测试与部署.py](../../projects/04-fastapi进阶/04.6-测试与部署/06-测试与部署.py) ｜ 测试套件：[test_06.py](../../projects/04-fastapi进阶/04.6-测试与部署/test_06.py)

## 核心概念

- **TestClient 原理**：FastAPI 的 app 本身就是 ASGI 应用；TestClient 不起服务器、不占端口，在进程内直接调用它——请求不经网络，毫秒级，还能精确断言状态码与响应体。
- **fixture = 准备与验证分离**：测试函数声明 `client` 参数，pytest 自动递进来（02.7 的兑现）。模块级 dict 活得比任何测试都久 → fixture 里 `reset_books()` 做状态隔离，否则测试产生顺序依赖。
- **dependency_overrides = 依赖的测试专属技能**：`app.dependency_overrides[get_session] = get_test_session`——业务代码一行不改，把真数据库整体换角成测试库（04.1 的 yield 依赖在此兑现）。
- **内存库的状态隔离新思路**：每个测试新建引擎、新内存 SQLite——「空书架」是天然的，不需要手动清数据。
- **TDD 循环**：先写测试（红，测试定义行为）→ 写实现 → 绿。

## 关键代码

```python
@pytest.fixture()
def db_client():
    test_engine = create_engine(
        "sqlite:///:memory:",
        connect_args={"check_same_thread": False},  # 04.1 老坑
        poolclass=StaticPool,   # 内存库默认每条连接各开一个空库；def 路由跨线程，必须共用连接
    )
    SQLModel.metadata.create_all(test_engine)

    def get_test_session():
        with Session(test_engine) as session:
            yield session

    db_app.app.dependency_overrides[db_app.get_session] = get_test_session
    with TestClient(db_app.app) as c:
        yield c
    db_app.app.dependency_overrides.clear()     # 拆除覆盖，不污染别的测试
```

## 常见坑

1. **内存库「建了表却看不见」**：不配 `StaticPool` 时每条连接各开一个空库，而 def 路由跑在线程池、每请求可能换线程——建好的表在别的线程不存在。`StaticPool` + `check_same_thread=False` 缺一就翻车。
2. **数字开头+中文文件名 import 不了**：`06-测试与部署` 不是合法 Python 标识符，只能 `importlib.util.spec_from_file_location` 按路径加载（顺带看穿 import 的本质：找到文件 → 执行一遍 → 拿到命名空间）。
3. **spec 可能是 None**：`spec_from_file_location` 返回 `ModuleSpec | None`，用 `assert _spec is not None` 收窄——Python 版的 TS `!` 非空断言（还兼当「文件必须在」的自检）。
4. **被测对象形状先看一眼**：04.1 的 `GET /books` 返回裸数组，06 的返回 `{"books": [...]}`——断言写错形状，报错是莫名的 `list indices must be integers`。
5. **部署是另一半**（本章只走了测试主线）：Uvicorn / Gunicorn、Docker 化留到项目实战章实践。
