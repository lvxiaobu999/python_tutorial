# 02.7 · 测试

> 练习代码：[test_stats.py](../../projects/02-python进阶/02.7-测试/test_stats.py)（被测模块是同目录的 [stats.py](../../projects/02-python进阶/02.7-测试/stats.py)）

## 核心概念

- **测试是「可重复执行的证明」**：改代码后跑一遍，几秒知道有没有改坏；读测试也是最快的了解模块用法的方式。pytest 是 Python 事实标准。
- **自动发现规则（约定零配置）**：文件 `test_*.py`、函数 `test_` 开头、类 `Test` 开头且不带 `__init__`，符合命名就自动被收集。
- **断言用裸 `assert`**：失败时 pytest 自动展示 `2 != 2.01` 这种左右值对比，不需要 unittest 的 `self.assertEqual` 那套。
- **参数化覆盖边界**：`@pytest.mark.parametrize` 让一份代码测多组数据，每组是独立测试；`59/60`、`89/90` 这类压线值最容易藏 bug，必须覆盖。
- **fixture 管准备与收尾**：函数名 = fixture 名，测试参数名一致就自动注入；`yield` 前是准备、后是清理；fixture 也能依赖别的 fixture（`tmp_path` 就是内置的）——和 FastAPI 的 `Depends` 依赖链同一个思想。
- **mock 把不可控变可控**：测「随机数、当前时间、网络请求」用假实现替换（如 `monkeypatch.setattr`），原则是**测自己的逻辑，mock 掉外部世界**。

## 关键代码

```python
import pytest

from stats import grade, mean


@pytest.mark.parametrize(
    ("score", "expected"),
    [(59, "E"), (60, "D"), (89, "B"), (90, "A"), (100, "A")],   # 边界值压线
)
def test_grade_boundaries(score: float, expected: str) -> None:
    assert grade(score) == expected


def test_mean_empty_raises() -> None:
    with pytest.raises(ValueError):            # 断言「这里会抛 ValueError」
        mean([])


@pytest.fixture
def sample_scores() -> list[float]:
    return [80, 90, 100]                       # 准备数据，测试间互不干扰


def test_mean_with_fixture(sample_scores) -> None:   # 参数名一致 → 自动注入
    assert mean(sample_scores) == 90
```

## 常见坑

- **测试函数里忘写 assert**（只调用了函数）：测试永远绿，等于没测。
- **测试间共享可变全局变量**：一个测试改了状态影响下一个，单独跑能过、一起跑就挂——测试要互不依赖。
- **想测「不抛异常」却写 `try/except: pass`**：异常被吞了，assert 根本没执行；直接裸调用 + assert 结果即可。
- **fixture 名和测试参数名不一致**：报 `fixture 'xxx' not found`。
- **只测正常路径**：空列表、0、None 这些边界和异常路径才是 bug 藏身处。
- **浮点比较直接 `==`**：`0.1 + 0.2 != 0.3`，要用 `pytest.approx`；数据偏差大时默认 `rel=1e-6` 太严，手动给 `abs=` 容差（见 `test_class.py`）。
- **测实现细节而非外部行为**：重构就崩，测试该保护的是「契约」。
