# 02.5 · 异步编程

> 练习代码：[01-异步并发.py](../../projects/02-python进阶/02.5-异步编程/01-异步并发.py)

## 核心概念

- **并发 vs 并行**：并行是多核「真同时」；并发是单线程里多任务交替推进、宏观上「一起」。asyncio 是单线程并发，不是并行。
- **什么任务适合异步**：IO 密集（网络请求、查数据库、读文件）→ asyncio，等待时可切换去干别的；CPU 密集（大量计算）→ 多进程，异步帮不上忙。记忆：**等待多 → 异步；计算多 → 多进程**。
- **`async def` 调用 ≠ 执行**：和调用生成器函数一样（02.3），只返回一个协程对象；`await` 才真正执行它并等结果。
- **`await` = 让出**：等待 IO 时当前协程挂起，把线程还给事件循环去跑别的协程——FastAPI 的高并发就建立在这上面。
- **事件循环**：一个不断转的单线程调度员，`asyncio.run(main())` 在最高层启动它，整个程序通常只调一次。
- **逐个 `await` 是排队，`asyncio.gather(*协程们)` 才是一起上**——本章核心。进阶用 `TaskGroup`（一个失败自动取消其余）和 `asyncio.timeout` 限时。

## 关键代码

```python
import asyncio
import time


async def job(seconds: float) -> str:
    await asyncio.sleep(seconds)      # 模拟网络 IO：此刻线程可以去跑别的协程
    return "done"


async def main() -> None:
    t = time.perf_counter()
    await job(1)                      # 串行：一个等完才轮到下一个
    await job(1)
    await job(1)
    print(f"串行 {time.perf_counter() - t:.1f} 秒")

    t = time.perf_counter()
    await asyncio.gather(job(1), job(1), job(1))   # 三个任务同时进入等待
    print(f"并发 {time.perf_counter() - t:.1f} 秒")


asyncio.run(main())
```

## 运行结果

```text
串行 3.0 秒      # 耗时 ≈ 各任务之和
并发 1.0 秒      # 耗时 ≈ 最长的那个（等待被共享了）
```

练习 2/3 实测：串行抓 3 个 0.5 秒的 url ≈1.5 秒，gather 并发 ≈0.5 秒；任务数改成 10 并发耗时几乎不变。

## 常见坑

- **只调用不 await**：`fetch("A")` 只创建协程没执行，看到 `RuntimeWarning: coroutine was never awaited`——协程对象必须被 await 或交给事件循环。
- **在 async 函数里用 `time.sleep(1)`**：它不放手，整个事件循环被卡住，所有协程都动不了；必须 `await asyncio.sleep(1)`。
- **逐个 `await` 以为是并发**：函数都是 async 的，但排队执行，结果一点没快——本章最核心的坑，练习 2 亲手对比过。
- **在普通 `def` 里写 `await`**：语法错误；async 函数之外跑协程要用 `asyncio.run`。
- **gather 里某个协程抛异常，其他任务不会自动取消**：还会继续跑完；要异常安全用 `TaskGroup`（它抛的是 `ExceptionGroup`，要配 `except*` 接）。
- **CPU 密集任务放 async 里毫无收益**：单线程里算 1 秒，谁也抢不到 CPU。
