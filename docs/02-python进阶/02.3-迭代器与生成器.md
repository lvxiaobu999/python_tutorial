# 02.3 · 迭代器与生成器

> 练习代码：[01-迭代器与生成器.py](../../projects/02-python进阶/02.3-迭代器与生成器/01-迭代器与生成器.py)

## 核心概念

- **可迭代对象 vs 迭代器**：可迭代对象只需 `__iter__`（list、str、文件对象……），迭代器还要 `__next__`——它是带游标的一次性取数器，负责「下一个是谁」。
- **for 循环的本质**：`iter()` 拿迭代器 → 反复 `next()` → 捕获 `StopIteration` 正常结束。for 不关心类型，只要求能给出迭代器（02.1 鸭子类型的体现）。
- **生成器函数**：函数体里出现 `yield`，调用它就返回生成器；每次 `next` 执行到 `yield` 暂停并交出值，下次从暂停处继续——它记住了执行位置和所有局部变量。
- **惰性求值**：调用生成器函数一行代码都不跑，有人消费才算下一个；所以无限序列（`fibonacci()`）也写得，大文件也流式读得了。
- **生成器表达式 `(x*x for x in ...)`**：与列表推导式 `[...]` 的区别是「要一个算一个、几乎不占内存」，但一次性、不能重复遍历、不能下标。
- **`yield from` 委托子生成器**：递归展平嵌套结构一行搞定；`itertools` 的 `islice`/`cycle`/`chain` 是现成的惰性积木。

## 关键代码

```python
from itertools import islice


def countdown(n):
    while n > 0:
        yield n                    # 交出值并暂停，下次从这行之后继续
        n -= 1


gen = countdown(3)                 # 调用不执行任何代码，只得到生成器
print(next(gen))                   # 第一次 next 才真正开始跑


def fibonacci():
    a, b = 0, 1
    while True:                    # 无限循环没问题：没人要就不算
        yield a
        a, b = b, a + b


print(list(islice(fibonacci(), 5)))           # 惰性流只取前 5 个
print(sum(x * x for x in range(5)))           # 生成器表达式：边流边算


def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:             # 文件对象本身就是惰性迭代器：一次只读一行
            line = line.strip()
            if line:               # 空行 strip 后为 ""，跳过
                yield line
```

```text

[0, 1, 1, 2, 3]

```

## 常见坑

- **生成器是一次性的**：耗尽后再 `for` 一次得到空序列——它不会重置，`iter(生成器)` 返回的还是它自己。要重复使用就再造一个，或干脆用 list。
- **调用生成器函数什么都不发生**：`countdown(3)` 一行没跑、`print` 出来是个 `generator object`——说明你还没遍历它，得 `next`/`for`/`list` 消费。
- **生成器里的 `return value` 不是把值返回给调用方**：而是结束生成并把 value 塞进 `StopIteration`，知道即可，别依赖。
- **生成器表达式当唯一实参可省外层括号**：`sum(x for x in ...)` 可以；参数多于一个就必须带上括号。
- **`groupby` 只对相邻元素分组**：数据没先按 key 排序，会得到意想不到的分组结果。
